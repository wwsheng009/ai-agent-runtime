# 01 · 需求分析与扩展

> 上游：[README.md](./README.md)｜下游：[02-architecture.md](./02-architecture.md)
> 本文把用户原始诉求拆成可验证的需求，并补全原始描述中未显式给出但业务闭环必需的项。

---

## 1. 原始诉求（复述与解读）

用户原始描述：

> 当前项目已有 `runtime-server` / `aicli tui` / `aicli micro web client` 三个用户入口，但面向外网使用不够方便。
> 需要设计一个 server 网关程序，提供**外网多会话管理接入**能力：
> - `aicli tui` 启动时，若配置了外部网关地址与接入 token，可以向网关注册会话信息；
> - `aicli tui` 可以启动 web micro client，并把服务地址向网关注册；
> - `runtime-server` 也可以类似地向网关注册 web 服务地址；
> - 网关提供 web 管理端，用户可切换 / 访问不同会话；
> - 网关部署到外网可直接访问的服务器，用户通过网关**反向访问**本地电脑的会话；
> - 可理解成一个 **hub**。
> - 先做需求分析与扩展，编写设计方案文档到 `docs/` 新目录。
> - 按最佳实践处理；**不需要多用户**；注重**多会话管理**、**广域网连接优化**、**移动端优化**、**整个业务闭环**。
> - 可以进一步优化 `micro web client` 或 `runtime-server`。

解读要点：

1. **网关是"反向接入 hub"**，不是又一个本地服务：本地主动注册、外网被动访问。
2. **多会话管理**是核心价值，而非多用户。
3. **连接质量**（广域网）与**移动端体验**是一等公民，不是后续优化。
4. 允许为达成闭环**改动** `micro web client` 与 `runtime-server`。

## 2. 角色与边界

| 角色 | 定义 | 说明 |
|------|------|------|
| Owner（唯一用户） | 网关的拥有者 | 单账号；可持有多个设备、多个会话；无团队/共享 |
| Device / Node | 一台机器上的一个接入进程 | 一个 `aicli TUI` 进程或一个 `runtime-server` 进程 = 一个 node |
| Session | 一次 agent 会话 | 归属某个 node；有独立 ID / 标题 / 运行态 |
| Gateway | 公网 hub | 注册表 + 反向代理 + 管理控制台 + 认证 |
| Agent | 内嵌在本地进程里的接入器 | 出站长连接、心跳、多路复用转发 |
| Client | 外网浏览器 / 移动端 | 访问网关控制台与会话页 |

**边界澄清（避免过度设计）**：

- 网关**不承载** agent 推理、不落会话正文、不代理 LLM 流量。
- 网关**不是** VPN：只暴露白名单化的本地 HTTP 路由，不是任意 TCP 隧道。
- 网关**不做**多租户、组织、RBAC、计费。

## 3. 场景（User Stories）

### 3.1 接入与发现

- **S1**：我在笔记本上 `aicli chat --gateway`，它自动连上网关并注册当前会话；我在手机浏览器打开网关，看到这台设备与这个会话。
- **S2**：我在服务器上跑 `runtime-server --gateway`，它把 Web 控制台地址注册到网关；我从公司电脑浏览器经网关打开它。
- **S3**：同一台机器开多个 `aicli` 窗口（多会话），网关控制台把它们**分组在同一设备下**，并可切换。
- **S4**：网关不可达 / 未配置时，本地 `aicli` 与 `runtime-server` 行为与今天完全一致（网关是可选增强）。

### 3.2 多会话管理与访问

- **S5**：网关控制台列出我所有设备的会话，带状态（idle/busy/等待审批/等待回答）与最后一条消息预览。
- **S6**：我点某个会话，直接在浏览器里看实时输出、发消息、批准/拒绝工具调用、回答提问、中断当前轮次。
- **S7**：我能在控制台里"切换会话"，而不用回到本机操作 TUI。
- **S8**：会话正文仍在本地；网关控制台只拿元数据，正文按需经隧道拉取。

### 3.3 广域网与弱网

- **S9**：本地网络抖动 / 换网后，隧道能自动重连并**续传**，不需要我在本机重启进程。
- **S10**：外网带宽差时，控制台自动降级为低带宽模式（少快照、纯文本、按需加载）。
- **S11**：长连接、SSE 流在弱网下不"假死"（有心跳与可观测的连接状态）。

### 3.4 移动端

- **S12**：我在手机上把控制台"添加到主屏幕"（PWA），像 App 一样打开。
- **S13**：会话等待审批 / 回答时，即使 App 在后台也能收到通知。
- **S14**：手机软键盘弹出时输入框不被遮挡，工具输出可折叠，横向不溢出。

### 3.5 运维闭环

- **S15**：我可以创建 / 撤销设备令牌；被撤销的设备立即断线且不能再注册。
- **S16**：我能看到设备在线状态、隧道延迟、最近错误与审计日志。
- **S17**：网关升级时与旧版 agent 有协议版本协商，不因版本不一致静默出错。

## 4. 功能需求（FR）

### 4.1 注册与生命周期

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-1 | 本地进程可按配置启动 gateway agent 并出站连接网关 | 配置 `gateway.url` / `gateway.token`（或 CLI flag / env）；未配置则完全不启动 |
| FR-2 | 注册携带节点元数据 | node_id（稳定）、kind、名称、版本、OS/架构、capabilities[]、workspace、会话列表 |
| FR-3 | 注册携带可反向访问的服务地址与路由白名单 | 例如 `base_url=http://127.0.0.1:<port>` + `routes=["/web","/web/api","/health"]` |
| FR-4 | 周期心跳与状态更新 | 心跳含会话状态（idle/busy/attention）与负载；会话切换/新建/结束时增量推送 |
| FR-5 | 优雅下线 | 进程退出尽力发送 `deregister`；网关侧超时判离线 |
| FR-6 | 断线重连与续传 | 指数退避 + 抖动；重连后以同一 node_id 恢复，会话状态重新对齐 |

### 4.2 多会话聚合

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-7 | 网关维护 node / session 两级注册表 | 支持一台设备多会话；同一会话只有一个 owner node |
| FR-8 | 会话元数据聚合查询 | `GET /api/sessions` 返回跨设备会话列表，支持按设备 / 状态 / 关键词过滤 |
| FR-9 | 会话"注意力"标记 | 等待审批、等待回答、运行中、出错、完成，均有稳定枚举 |
| FR-10 | 会话路由 | 每个会话可解析到 `node → tunnel → 本地路由` |

### 4.3 反向访问（透明代理）

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-11 | HTTP 方法 / 头 / body 保真转发 | GET/POST/PUT/DELETE/PATCH、查询串、请求头、分块 body |
| FR-12 | SSE 流式保真 | `/web/api/events` 等长连接经隧道持续推送，`X-Accel-Buffering: no`，可断线续订 |
| FR-13 | 下载保真 | `Content-Disposition`、`Content-Type`、`Range`、`HEAD` 语义不丢 |
| FR-14 | 上传保真 | 分片 / 大 body 有流控，不整包进内存 |
| FR-15 | 本机令牌由 agent 注入 | 浏览器 / 网关不接触 `X-AICLI-Token`、admin token |
| FR-16 | 路由白名单 | 只转发允许的路径前缀，拒绝任意路径（防开放代理） |

### 4.4 管理控制台

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-17 | Owner 登录 | 单账号；HttpOnly Cookie 会话；支持退出 |
| FR-18 | 设备 / 会话总览 | 在线状态、最后活跃、注意力徽标、预览 |
| FR-19 | 会话打开与切换 | 内嵌会话视图（复用微前端），可在会话间切换 |
| FR-20 | 设备令牌管理 | 创建（仅显示一次）、撤销、查看最近使用 |
| FR-21 | 审计与状态 | 登录、令牌变更、会话访问、隧道异常可查 |

### 4.5 本地进程改造

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-22 | `aicli TUI` 支持 gateway 配置与启动 | flag / 配置 / env 三选一；启动后打印网关访问地址 |
| FR-23 | `runtime-server` 支持 gateway 配置与启动 | 同上；只监听回环，绝不因网关而绑定公网 |
| FR-24 | `micro web client` base-path 感知 | 被网关以路径前缀代理时，相对/绝对请求仍正确 |
| FR-25 | `micro web client` 移动优先 | 响应式布局、软键盘安全、可折叠、PWA 清单 |

### 4.6 通知与会话 Web UI 反向访问

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-26 | **事件驱动通知**：turn 完成 / 待审批 / 待回答 / 出错时通知用户 | agent 订阅**本地运行时事件总线**（`agent.turn.finished`/`approval_requested`/`question_asked`/`turn.suspended`/失败）派生 `attention` + 瞬时 `NOTIFY`；控制台徽标/收件箱/toast + **Web Push / ntfy 双通道**；**通知不含正文**；presence 抑制与去重 |
| FR-27 | 用户切换会话即反向代理打开本机 Web UI | 控制台 iframe 载入 `/s/{id}/web/`（aicli 微前端）或 `/s/{id}/`（runtime-server SPA），网关反向代理到本机回环；base-path 感知、同源 Cookie、本机令牌由 agent 注入 |
| FR-28 | 复用而非新增 hook | 通知**不新增 hook**、不侵入 turn 路径；现有 `internal/hooks`（`stop`/`stop_failure` + shell/http）保留为用户自定义外呼扩展点 |

### 4.7 连接控制面（手动连接 / 断开）

| 编号 | 需求 | 验收要点 |
|------|------|----------|
| FR-29 | `aicli TUI` 新增命令手动连接 / 断开 / 重连 / 查看状态 | `/gateway [status\|connect\|disconnect\|reconnect\|url\|enable\|disable]`；`disconnect` 为运行态（抑制自动重连、不改配置），`enable/disable` 才写配置 |
| FR-30 | `runtime-server` 前端暴露连接控制入口 | 设置页 "Gateway"：状态 + 连接/断开/重连 + 配置（url/令牌/名称/自动连接）；过渡态禁用按钮 |
| FR-31 | 控制 API 与共享接口 | `/api/runtime/gateway/{status,connect,disconnect,reconnect,config}`；`internal/gateway/agent.Controller` 两宿主共用；**不回传令牌明文**；仅本机 owner 可触发 |

## 5. 非功能需求（NFR）

| 类别 | 编号 | 需求 | 目标 |
|------|------|------|------|
| 性能 | NFR-1 | 隧道复用 | 每 node 只维持 **1 条** 长连接（不含重连），多请求多流复用 |
| 性能 | NFR-2 | 附加延迟 | 网关转发相对本地直连的额外延迟，同区域 P50 < 30ms，P95 < 80ms |
| 性能 | NFR-3 | 首字节 | 控制台会话首屏（含首帧）在 4G 下 < 2.5s |
| 性能 | NFR-4 | 内存 | 单会话转发不整包缓冲；网关单流缓冲上限可配（默认 ≤ 256KB） |
| 可靠性 | NFR-5 | 重连 | 隧道断开后 1s 起退避重连，5 分钟内恢复；恢复不丢会话归属 |
| 可靠性 | NFR-6 | 降级 | 网关不可用时本地功能零影响；控制台不可用时本地 TUI 零影响 |
| 可靠性 | NFR-7 | 幂等 | 重复注册 / 重复心跳安全；旧连接被新连接接管（fencing） |
| 安全 | NFR-8 | 全链路 TLS | 浏览器→网关、agent→网关均 TLS；禁止明文 |
| 安全 | NFR-9 | 令牌最小暴露 | 设备令牌仅存哈希；本机令牌永不出本机；浏览器仅持 owner 会话 Cookie |
| 安全 | NFR-10 | 白名单转发 | 非白名单路由一律 403；禁止开放代理 |
| 安全 | NFR-11 | 限流 | 登录、注册、转发均有速率限制；单 owner 连接数上限可配 |
| 可观测 | NFR-12 | 指标 | 在线节点数、活跃隧道数、流数、字节、错误率、重连次数、延迟分位 |
| 可观测 | NFR-13 | 日志 | 结构化日志 + 审计事件；不含会话正文与令牌原文 |
| 兼容 | NFR-14 | 版本协商 | 协议 major 不匹配时明确拒绝并给出升级提示，不静默失败 |
| 移动 | NFR-15 | 触控与视口 | 触控目标 ≥ 44px；软键盘不遮挡；`visualViewport` 适配 |
| 移动 | NFR-16 | 可安装 | 提供 manifest + service worker，可"添加到主屏幕" |
| 移动 | NFR-17 | 低带宽 | 提供显式低带宽开关与自动探测；纯文本模式可用 |
| 移动 | NFR-18 | 后台通知 | 会话需注意力时可按需推送（Web Push；FCM/WNS 不可达时可经自建 ntfy 兜底） |

## 6. 约束与假设

**约束**

- C1：本地进程**不得**为了接入网关而监听公网地址；只能出站连接。
- C2：不引入多用户 / 团队 / RBAC；认证模型保持"单 owner"。
- C3：优先复用现有依赖（`gorilla/websocket`、`gorilla/mux`、`golang.org/x/net`），不引入重量级隧道/服务网格依赖。
- C4：网关只做注册表 + 路由 + 控制台，不复制会话正文。
- C5：与现有回环安全模型兼容：agent 转发时以本机回环身份 + 注入令牌通过本机 Host/Origin 校验。

**假设**

- A1：Owner 能自行提供一个有公网 IP / 域名与 TLS 证书的服务器（或用反代 / LB 终止 TLS）。
- A2：本地进程能出站访问 `443`（或自定义端口）。
- A3：本地 `aicli` / `runtime-server` 与网关使用同一份代码仓库构建（版本可对齐）。
- A4：usage ledger 的 SQLite 默认 DSN 为 `~/.aicli/data/usage_ledger.db`（`configs/config.yaml:93`，
  原 `./data/gateway.db`，非网关产物，见 [02](./02-architecture.md) §8.1）；网关数据文件使用
  `gateway-registry.db`，不复用 ledger 文件。
- A5：`aicli` / `runtime-server` **已有** hook 系统（`internal/hooks`：`stop`/`stop_failure` + shell/http）
  与运行时事件总线（`agent.turn.finished` / `approval_requested` / `question_asked` …），
  通知能力基于**已有事件总线**实现，不改变 hooks 语义（见 [08](./08-notifications.md)）。

## 7. 非目标（Non-Goals）

- NG1：多租户 SaaS、组织/团队、细粒度 RBAC、计费。
- NG2：在网关上运行 agent / 工具 / LLM。
- NG3：任意 TCP/UDP 隧道或 VPN（只做白名单 HTTP 反向代理）。
- NG4：替代 `aicli-mesh`（mesh 继续负责单机多进程发现与治理）。
- NG5：端到端加密（E2EE）到浏览器——首期以 TLS + 网关可信为前提；E2EE 列入远期可选（见 04 文档）。
- NG6：本地会话历史/正文上云。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 把本机会话暴露到公网 | 高 | 全链路 TLS + owner 登录 + 设备令牌可撤销 + 路由白名单 + 审计 + 限流；本地令牌不出本机 |
| 反向代理路径重写脆弱（绝对 URL、SSE） | 中 | 让 `micro web client` **base-path 感知**为主，响应改写为兜底；SSE 用流式帧透传 |
| 重连风暴 / 惊群 | 中 | 指数退避 + 抖动 + 心跳错峰；网关侧连接接管（fencing） |
| 流式背压导致网关内存膨胀 | 中 | 每流信用窗口 + 缓冲上限 + 慢消费者策略（丢弃/合并高频 delta） |
| 网关单点故障 | 中 | 无状态网关 + 外部注册存储；隧道态用一致性哈希/会话粘滞；HA 列入 Phase 3 |
| 版本漂移 | 低 | 协议版本协商 + 明确错误码；agent 与网关同仓构建 |
| 移动端浏览器后台挂起 SSE | 中 | 前台恢复时按 `Last-Event-ID`/`since_seq` 续订 + 推送兜底 |
| `gateway.db` 命名冲突 | 低 | **已解决**：ledger 改名 `usage_ledger.db` 并锚定 `~/.aicli/data/`；网关用 `gateway-registry.db`（见 02 §8.1） |

## 9. 成功判据（Definition of Done）

1. 未配置网关时，`aicli` / `runtime-server` 行为与现状**逐字一致**（有回归测试）。
2. 配置网关后，本地进程**不开放任何公网端口**，控制台能看到设备与会话。
3. 从外网浏览器能对本地会话完成：看实时输出 → 发消息 → 审批/回答 → 中断 → 切换会话（全链路闭环）。
4. 隧道断开重连后，控制台无需人工干预即可恢复会话访问。
5. 移动端浏览器可安装为 PWA，软键盘不遮挡输入，弱网下可切低带宽模式。
6. 撤销设备令牌后，该设备立即离线且无法再注册。
