# 05 · 广域网连接优化与移动端优化

> 上游：[02-architecture.md](./02-architecture.md)、[03-protocol.md](./03-protocol.md)
> 本文把"广域网连接优化"与"移动端优化"拆成可实施、可度量的条目。
> 两个优化面是**不同链路**，不要混为一谈：

```text
   移动端浏览器 ──(A: 公网 HTTPS/HTTP2/3，弱网、易断)──▶ 网关
   网关        ──(B: 隧道 wss，跨地域、NAT、抖动)──────▶ 本机 agent
```

- **链路 A（浏览器↔网关）**：移动端优化的主战场（PWA、推送、视口、低带宽、断线续订）。
- **链路 B（网关↔agent）**：广域网连接优化的主战场（多路复用、压缩、续传、背压、重连）。

---

## 1. 链路 B：广域网连接优化

### 1.1 单连接多路复用（基础）

- 每 node **只维持 1 条** WS/TLS 长连接（不含重连过渡期），所有请求/SSE 复用该连接。
- 收益：消除每请求 RTT + TLS 握手；绕开 HTTP/1.1 每 host 6 连接上限；NAT 友好。
- 实现：`internal/gateway/wire` 帧 + 每流信用窗口（见 03 文档 §5）。

### 1.2 压缩

| 项 | 策略 |
|----|------|
| 隧道层 | WebSocket `permessage-deflate`（协商；弱网开，高速内网可关） |
| 响应体 | 网关对下游浏览器响应按 `Accept-Encoding` 做 gzip/br（若上游未压缩）；避免"双重压缩" |
| 屏幕快照 | **差分**优先（§1.4），其次压缩 |
| 已压缩内容 | `image/*`、`application/gzip`、`application/zip`、`font/*`、已有 `Content-Encoding` 的响应：**不再压缩** |

### 1.3 心跳、重连与抖动

- 应用层 `PING/PONG`：每 20s（与 mesh 默认 30s 心跳错开，避免同拍）。
- 判活：连接存活 **且** 心跳新鲜（TTL 90s，与 mesh 一致）。
- 重连：指数退避 `1s→2s→4s→…→30s`，抖动 ±20%；`GOAWAY{restart}` 触发**立即短退避**重连。
- 连接接管（fencing）：同 node_id 新连接到达 → 旧连接 `GOAWAY` 后关闭，避免"双活"。
- 避免惊群：重连退避加抖动；网关侧对同 node_id 的注册做去抖。

### 1.4 屏幕与事件增量（降低带宽）

现状：微前端已有 `/web/api/screen`（完整快照 + `?tail` / 窗口）与 `/web/api/events`（SSE 增量）。
优化：

- **屏幕差分**：新增 `delta_screen` 能力——agent 侧对 `screen` 快照做结构化 diff（按消息行/块），
  只推变化部分；首帧全量，后续差分。网关缓存"该流最后一次全量 + 版本号"，差分基于版本号，
  丢失时回退全量（`If-None-Match`/版本协商）。
- **事件合并**：token 级 delta 事件在**时间窗**内合并（如 50ms）后 flush，减少小包；
  保持 SSE 语义（同一 `event:` 的连续 `data:` 行可合并；不跨 event 合并）。
- **屏幕快照节流**：低带宽/后台时降低快照频率（移动端尤其），改为"事件驱动 + 空闲全量"。

### 1.5 背压与慢消费者

- 每流信用窗口（默认 1MiB）；慢消费者先背压到 agent，让本机也慢下来。
- 超时后按流类型分级：
  - **可丢弃**（屏幕快照）：只保留最新，丢旧帧（标注 `dropped`）。
  - **不可丢弃**（SSE 事件流、下载）：保持背压；SSE 断线用 `Last-Event-ID` 续传。
- 单连接总缓冲 8MiB / 单流 256KB 上限，超限按上表处置。

### 1.6 传输升级（Phase 3 可选）

- **QUIC / HTTP/3**：agent 切换网络（Wi-Fi↔蜂窝）时连接迁移不中断；多流无队头阻塞。
- 协议帧不变，仅换承载；网关与 agent 协商 `transport=ws|h3`。
- 代价：`quic-go` 新依赖 + 部署复杂度；**非首期必需**，列入 Phase 3。

### 1.7 度量

| 指标 | 目标 |
|------|------|
| 隧道 RTT（P50/P95） | 用于展示与自适应 |
| 重连次数 / 小时 | < 2（稳定网络） |
| 转发额外延迟（相对本地直连） | P50 < 30ms，P95 < 80ms |
| 带宽节省（差分+合并） | 相对全量快照降低 ≥ 60%（长会话） |
| 慢消费者丢弃率 | 可观测，默认目标 < 1% |

## 2. 链路 A：移动端优化

### 2.1 控制台移动优先（PWA）

- **响应式**：会话列表在窄屏为单列卡片；会话视图全屏；侧栏改为抽屉。
- **PWA**：`manifest.webmanifest`（名称、图标、`display: standalone`、主题色）+ service worker：
  - 缓存应用外壳（HTML/JS/CSS/图标）→ 秒开；
  - **不缓存** API 与 SSE（数据必须实时）。
- **安装提示**：首次访问展示"添加到主屏幕"引导。
- **触控**：触控目标 ≥ 44×44px；避免 hover-only 交互；支持滑动手势（如左滑返回会话列表）。
- **暗色模式**：跟随系统（`prefers-color-scheme`）。

### 2.2 软键盘与视口

- 使用 `visualViewport` API 处理键盘弹出：输入框 `position: sticky; bottom: env(safe-area-inset-bottom)`。
- `viewport` meta：`width=device-width, initial-scale=1, viewport-fit=cover`（配合安全区）。
- 输入区在键盘弹出时**上移**而非被遮挡；发送后保持焦点（移动端连续输入）。
- 防止 iOS 聚焦缩放：输入 `font-size ≥ 16px`。

### 2.3 会话列表与注意力

- 卡片显示：标题、设备名、状态徽标、最后消息预览（截断）、相对时间。
- **注意力徽标**：等待审批 / 等待回答 / 运行中 / 出错 / 完成（稳定枚举，见 02 文档 §3.2）。
- 顶部聚合："N 个会话需要处理"。
- 分组：按设备分组；同设备多会话折叠。
- 过滤 / 搜索：状态、设备、关键词。

### 2.4 会话视图（复用并改造微前端）

- **可折叠工具输出**：默认折叠长工具输出，点击展开（移动端屏幕宝贵）。
- **专注模式**：隐藏侧栏/元信息，只留 transcript + composer。
- **横向不溢出**：代码块/表格可横向滚动（`overflow-x:auto`），不撑破布局。
- **图片/附件**：懒加载 + 占位；弱网可"仅文本"。
- **审批/提问卡片**：移动端大按钮（批准/拒绝/选项），一屏可完成。

### 2.5 后台与推送

- **SSE 后台挂起**：移动浏览器切后台会挂起 SSE。恢复前台时：
  - 先 `GET` 一次当前快照对齐状态；
  - 再按 `Last-Event-ID` / `since_seq` 重连 SSE 续订。
- **Web Push（可选）**：会话进入 `attention=approval|question|completed` 时，网关发 Web Push
  （需 service worker + 订阅端点；网关持有订阅并转发 agent 的注意力事件）。
  - 隐私：推送内容只含"某会话需要处理"级别，不含正文；点击打开对应会话。
- **通知去重**：同一会话同一注意力状态在时间窗内只推一次。

### 2.6 低带宽模式

- **自动探测**：`navigator.connection.effectiveType`（`2g/3g`）或实测 RTT/吞吐 → 建议降级。
- **显式开关**：用户可手动切"低带宽/纯文本"。
- 低带宽行为：
  - 屏幕改为**差分 + 节流**（如 1s 合并窗口）；
  - transcript 默认只渲染最近 N 条，历史按需加载（分页）；
  - 图片/附件默认不自动加载；
  - 关闭非必要轮询（余额、分析等）。
- 状态可视化：顶部显示当前模式与估算带宽。

### 2.7 移动端度量

| 指标 | 目标 |
|------|------|
| 首屏可交互（4G，冷启动） | < 2.5s |
| 首屏可交互（PWA 二次打开） | < 1s |
| 会话切换（列表→可交互） | < 1.5s |
| 弱网（Slow 3G）可用性 | 纯文本模式可完成"看输出 + 发消息 + 审批" |
| 横向溢出 | 0（自动化截图/视口检查） |
| 键盘遮挡 | 0（真机/模拟器检查） |

## 3. 自适应策略（A + B 联动）

网关维护每条隧道与每个客户端的"质量画像"，据此调参：

| 观测 | 调整 |
|------|------|
| 隧道 RTT 高 / 丢包 | 提高压缩、增大合并窗口、降低快照频率 |
| 浏览器 `effectiveType` 差 | 切低带宽模式、延迟加载图片/历史 |
| 慢消费者持续 | 分级丢弃（快照）/ 背压（事件流） |
| 频繁重连 | 增大心跳容差、延长退避上限、提示网络问题 |

所有自适应都应有**显式可见状态**（用户能看到"当前低带宽"）与**手动覆盖**（避免"聪明反被聪明误"）。

## 4. 与现有实现的对接点

| 优化项 | 现有基础 | 需要新增 |
|--------|----------|----------|
| SSE 合并/节流 | 已有 SSE 事件流与合并思路（`docs/plan/sse-live-event-channel-optimization-plan.md`） | 网关侧合并窗口（不改变 SSE 语义） |
| SSE 续传 | 微前端 `/web/api/events?since_seq=`、`Last-Event-ID` | 网关透传 `Last-Event-ID` |
| 屏幕快照 | `/web/api/screen`（完整/窗口/过滤） | `delta_screen` 差分协议 + 版本号 |
| h2c 连接预算 | aicli 回环已用 h2c 复用连接（`pprof.go`） | 隧道层已是单连接多流，无需 h2c |
| 微前端页面 | `backend/cmd/aicli/commands/web/*`（`//go:embed web`，零构建） | base-path 感知 + 移动优先布局 + PWA |
| 网关控制台 | 新增**轻量独立控制台**，范式对齐微前端（`//go:embed console/` + 零构建） | 见 [07-console.md](./07-console.md) |
| 完整工作台 | `frontend/`（React/Vite，runtime-server 用） | 经 `/n/{node}/` 反向访问即可；网关控制台不重复实现其 UI |

## 5. 优化验收清单（可勾选）

- [ ] 每 node 仅 1 条隧道连接，多请求/SSE 复用（连接数断言）
- [ ] 隧道断线后自动重连并恢复会话访问，无需人工干预
- [ ] 慢消费者场景下网关内存有界（压力测试）
- [ ] SSE 在弱网/切后台后按事件 ID 续订，不丢事件
- [ ] 长会话（>500 消息）在差分模式下带宽显著下降（对比全量快照）
- [ ] 移动端控制台可安装为 PWA 并秒开
- [ ] 软键盘不遮挡输入（真机/模拟器）
- [ ] 低带宽模式下可完成核心闭环（看/发/审批）
- [ ] 所有自适应状态对用户可见且可手动覆盖
