## 2. 分层 → 工作项映射（对齐 `02` §2）

| 层 | `02` 中的落点 | 工作项 | 交付物（可验证） |
| --- | --- | --- | --- |
| L1 归属层 | 2.1 | **W1 文件归属判定** | 一个 `HandlesFile` 式判定：给定文件路径 → 该 server 是否处理。通知与诊断两条路径**都必须先过这层过滤** |
| L2 生命周期层 | 2.2 | **W2 客户端池与启停** | 池的生命周期由**宿主**持有（按 `adr/0002`）；启动失败/不可用时记录为"不可用"状态而非抛出中断会话 |
| L3 路由层 | 2.3 | **W3 路径→client 路由** | 路由结果与 W1 判定一致；多 server 命中时按 `02` §5.1 `lsp_servers` 既有语义（去重/优先级见 Q4） |
| L4 同步层 | 2.4 | **W4 变更通知** | 编辑落盘后触发 `didChange`/`didSave`；只通知 W1 判定为"归属"的 client |
| L4 同步层 | 2.4 | **W5 诊断读取** | 读取当前版本的诊断快照，供 W6 内联 |
| L5 工具层 | 2.5、§3 | **W6 编辑工具尾部内联诊断**（**核心工作项**） | 编辑成功 → 通知 → 读诊断 → **追加**到原返回文本尾部；形态见 §6 不变量 I1/I2 |
| L5 工具层 | §3.2 | **W7 诊断查询工具（可选）** | 独立工具，仅在 W6 拿不到（无归属 client）时作为补充路径；不作为主反馈环 |
| L6 呈现/持久层 | 2.6 | **W8 持久化** | 只写现有列 `lsp_diagnostics`、`lsp_servers`，**不加列、不加表**（见 §6 不变量 I4） |

拆分原则：W1/W2 先于 W3/W4；W4 先于 W5/W6；W6 是闭环成立的最小集（缺任一环，"同一次 tool call 内闭环"就不成立）。

## 4. 配置项（阈值**不得写死**）

来源：`02` §1.2 第 3 行（"不拍板诊断数量上限等阈值 → 见 §6，转 `03` 验收"）、§2.6（阈值进入验收）、§6.2 Q1/Q2/Q5。

以下为**配置键草案**，最终命名与层级以 `knowledge_Layer` 的配置规格为准（本目录无权定稿）：

| 配置项（草案） | 作用 | 默认值策略 |
| --- | --- | --- |
| `diagnostics.scope` | `all`（全量文件诊断，crush 行为） / `changed`（只报本次改动引入，Q1） | 切换必须能靠配置完成，不能改代码 |
| `diagnostics.max_items` | 单次内联诊断条数上限 | 必须有上限；具体值由 M5 压测后填 |
| `diagnostics.max_chars` | 内联诊断的字符预算（Q2） | 同上；超预算的截断策略需固定且可解释 |
| `diagnostics.wait_ms` | 编辑后等待诊断的时延上限（Q5） | 必须有上限；超时按 Q3 的降级语义返回 |
| `diagnostics.degrade_mode` | LSP 缺失/超时时：返回空 / 返回提示 / 失败（Q3） | 三选一，且行为可被消息内容区分 |

验收要求：上述每一项都能**在不改代码**的情况下改变行为（配置化本身是验收项 A5）。

## 5. 验收清单（逐条关闭 `02` §6.2）

### A1 · 闭环形态（对应 `02` §3，不变量 I1/I2）
- **判定方法**：对一次会引入语法错误的编辑，检查编辑工具的单次返回体。
- **通过**：原始编辑结果文本**一字未删**，诊断**追加在尾部**；模型无需额外调用第二个工具即可看到该错误。
- **不通过**：诊断替换了原文本；或需要模型再发一次 `diagnostics` 调用才发现。

### A2 · 归属过滤（L1）
- **判定方法**：构造一个**不属于**任何已启动 server 的文件，执行编辑并观察是否产生通知/诊断读取。
- **通过**：通知与诊断两条路径都因归属判定被跳过，无多余日志与外呼。
- **不通过**：对该文件仍发出 `didChange`，或仍尝试读取诊断。

### A3 · 位置编码边界（`adr/0006` 规则 4.4 "转换只发生在边界 (D3)"）
- **判定方法**：构造含非 ASCII（如中文/emoji）的行，比对 LSP 报回的 position 与内部使用的 offset。
- **通过**：UTF-16 ↔ 字节 offset 的转换**只发生在边界**（协议出口/入口），内部一律使用字节 offset；缓存键按 `adr/0006` 的规则组合，**不得**在工具层再做一次转换。
- **不通过**：工具层/编辑层出现第二处编码转换，或非 ASCII 行诊断定位偏移。

### A4 · 持久化边界（L6）
- **判定方法**：检查实现是否只写入既有列。
- **通过**：诊断与 server 状态落在既有列 `lsp_diagnostics`、`lsp_servers`；**除上游 ADR 已授权的列（ADR-0006 `position_encoding`，Gate = `Phase4-start`）外无新增列/新增表**；重开会话可读回。
- **不通过**：为"顺手"新增上游 ADR 未授权的字段。
- **若确认既有列语义不够**：不在本目录补规格，走 §7 回流 `knowledge_Layer`。

### A5 · 配置生效（对应 §4 全部配置项）
- **判定方法**：对每个配置项做一次"改配置 → 行为变化"的对照实验。
- **通过**：行为按预期变化（含"把上限压到 1"这种极端值），且无写死路径短路。
- **不通过**：配置存在但代码里另有硬编码上限/超时。

### A6 · Q1 诊断粒度：全量 vs baseline 差分
- **判定方法**：在同一文件既有若干历史诊断的前提下做一次编辑，对比 `diagnostics.scope=all` 与 `changed` 两种模式的噪声量与 token 增量。
- **通过**：两条路径都能跑通；**结论（选哪种或缺省）需以数据写回本文档表格**，不允许"因为 crush 这样所以这样"。
- **需回流的情形**：若"changed"需要规格层的 diff 语义支持 → 记入 §7 回流项。

### A7 · Q2 token 预算与截断策略
- **判定方法**：制造诊断数远超 `max_items` / `max_chars` 的文件并编辑。
- **通过**：截断点固定、可解释（例如按严重度再按行号），且截断本身在返回体里**可被模型看出来**（如标注"已截断 N 条"）。
- **不通过**：静默丢弃高严重度诊断。

### A8 · Q3 降级语义
- **判定方法**：分别停用 LSP、制造超时，各做一次编辑。
- **通过**：三种模式（空/提示/失败）行为与消息内容可区分；**不影响编辑本身的成功返回**。
- **需回流的情形**：口径若与工具返回体规格冲突 → §7。

### A9 · Q4 多 server 去重与优先级
- **判定方法**：同时启用两个会处理同一文件的 server，触发重叠诊断。
- **通过**：重复项被合并或按固定规则排序，规则**可被文档化描述**。
- **需回流的情形**：该规则实质是对 `lsp_servers` 既有语义的**解释权**问题 → 归规格侧，不在 `docs/lsp` 拍板（`02` §6.2 Q4 原文如此）。

### A10 · Q5 编辑后等待时延
- **判定方法**：压测编辑工具调用耗时，含 `diagnostics.wait_ms` 命中与不命中两种情况。
- **通过**：阻塞时长有上限且可观测（日志/指标）；超时走 A8 的降级语义，**不产生无限等待**。

### A11 · 刻意差异被承认（`02` §6.3）
- **判定方法**：逐条核对 4 行差异（运行形态、LSP 缺失为常态、同步等待需上限、诊断粒度待定）。
- **通过**：提示词中**显式写明"LSP 可能不存在"的降级预期**（`02` §4.2 第 3 点）；任何一处按 crush 原样照搬即判不通过。

## 6. 不变量（回归时优先看这几条）

- **I1**：编辑成功的返回文本是**追加**语义，不是替换。
- **I2**：闭环发生在**同一次 tool call**内。
- **I3**：归属判定（W1）在通知与诊断两条路径上**都要过**。
- **I4**：持久化只用现有列，**本目录**不新增 schema；上游 ADR 已授权的列（如 ADR-0006 的 `position_encoding`，Gate = `Phase4-start`）不在此约束内，落地时按 ADR 执行。
- **I5**：位置编码转换**只在边界**发生一次（`adr/0006` 4.4）。
- **I6**：所有阈值来自配置，代码内无硬编码上限/超时。
